# 主方案TXT补齐记录：RUN-20260807-REBATEX60-001

## 问题

首版交付只有 `GJBTScheme/高级倍投主配置.txt`，5个号码方案仅保存为JSON定义，没有对应的软件主方案TXT。该交付对用户不可直接导入，属于交付完整性缺陷。

## 恢复证据

历史验证档案已确认：

- `高级定码轮换 + 前二 + 直选复式` 曾由用户人工导入成功；
- 前二属于2段格式；
- 已验证格式示例为 `高级定码轮换内容=1|012-123|1|1`；
- 主方案使用GBK无BOM、CRLF；
- 高级倍投主配置继续使用UTF-8 BOM、CRLF；
- 当前正式规则要求高级倍投主方案使用 `倍投类型=1`、`倍投方案=高级倍投主配置`。

因此，本批固定精确二码使用与语义一致的 `高级定码轮换` 载体，而不再用“高级开某投某”包装常量映射。

## 可复算生成器

`tools/build_front2_60_txt_bundle.py`

生成器对5个TXT强制检查：

- GBK无BOM；
- CRLF；
- 第1/2行；
- 前二+直选复式；
- 高级倍投引用；
- 两段固定二码；
- `SchemeCreator=` 为空。

## 尚未解除的运行风险

TXT缺失问题已修复，但这不自动解除多方案高级倍投状态同步风险。五方案同时投注时，软件是否让5个方案共享同一高级倍投ID、以及任一方案命中后是否让其余4个方案一起复位，目前仍缺E3运行证据。

因此：

- `MAIN_TXT_MISSING`：已解决；
- `ADVANCED_MULTI_SCHEME_STATE_NOT_E3`：仍保留；
- 平台实际返奖/返点/限额未冻结：仍保留。

正式资金启动前必须做最小金额同步状态探针，不能因为TXT可导入就把组合回利数学等同于已验证实盘行为。
