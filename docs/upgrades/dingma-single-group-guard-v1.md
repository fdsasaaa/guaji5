# 定码轮换单组号码强制闸门 V1

## 缺陷

此前生成器把三个投注号码组写进同一个 `定码轮换内容` 字段：

```text
定码轮换内容=8 6 3;7 2 9;4 0 1
```

这是错误格式。分号不能在普通定码轮换的投注号码字段中承担“多组投注”含义。

## 强制规则

普通定码轮换中，一个方案 TXT 只能保存一个投注号码组，号码之间使用空格：

```text
方案863：定码轮换内容=8 6 3
方案729：定码轮换内容=7 2 9
方案401：定码轮换内容=4 0 1
```

需要三组投注时，必须生成三个独立方案 TXT。随后按真实需要选择一种编排方式：

1. 组合方案出号引用三个子方案；
2. 组合方案轮投引用三个子方案；
3. 在 GUI 顶部勾选方案轮投，让三个已勾选方案逐期循环。

禁止依靠普通投注号码字段中的分号、中文分号或其他自造分隔符模拟多方案。

## 分号白名单

分号只允许保留在已有结构语法中：

- `高级定码轮换内容` 的多局结构；
- `组合方案出号内容` 的方案名称引用；
- `组合方案轮投内容` 的多局结构；
- `GJBTScheme/高级倍投主配置.txt` 的固定九字段结构；
- GUI 顶层多方案引用。

白名单是按字段和文件结构判定，不是“看到多组就可以用分号”。

## 自动拦截

`05_工具/audit_scheme_semantics.py` 已加入单方案单号码组检查：

- 拒绝英文分号 `;`；
- 拒绝中文分号 `；`；
- 报错信息明确要求拆成多个方案；
- 保留结构型分号白名单；
- CI 对自测案例及 PR 中新增/修改的 TXT、ZIP 执行审计。

## 回归案例

| 案例 | 预期 |
|---|---|
| `定码轮换内容=8 6 3` | 通过 |
| `定码轮换内容=8 6 3;7 2 9;4 0 1` | 失败 |
| `定码轮换内容=8 6 3；7 2 9` | 失败 |
| `组合方案出号内容=方案863;方案729;方案401` | 通过 |
| `高级定码轮换内容=1|0 2|1|1;2|3 4|1|1;` | 通过 |

本次构建类型：`SYSTEM_UPGRADE_ONLY`。
