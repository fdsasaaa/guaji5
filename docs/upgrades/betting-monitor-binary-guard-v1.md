# 投注监控二进制格式闸门 V1

## 问题

系统曾生成包含0和1以外内容的投注监控序列。该字段不是普通数字参数，也不是开奖号码、期数或倍数列表。

## 唯一语义

- `0`：挂，即上一期按当前方案判定未中；
- `1`：中，即上一期按当前方案判定命中；
- 序列从左到右按连续历史结果匹配；
- `0011`：连续出现挂、挂、中、中后开始投注。

## 合法格式

```text
投注监控=False-
投注监控模式=0
```

或：

```text
投注监控=True-0011
投注监控模式=0
```

仅开始监控可使用：

```text
投注监控=True-101010
投注监控模式=1
```

## 强制禁止

- 监控序列中出现2—9；
- 空格、逗号、分号或其他分隔符；
- 直接写“挂挂中中”等中文；
- 把开奖号码、期数、倍数或投注号码塞入序列；
- `True-`后为空；
- 关闭状态后仍附带监控序列；
- 启用监控却缺少 `投注监控模式`；
- `投注监控模式`使用0和1以外的值。

## 机器防线

- 正式策略：`betting_monitor_policy.json`；
- 语义审计：`05_工具/audit_scheme_semantics.py`；
- CI自测覆盖合法关闭、0011、仅开始监控，以及数字2、中文、空格、空序列、关闭附带序列、非法模式和缺失模式等错误；
- 任一方案TXT或方案ZIP触发错误时，交付与PR校验失败。

## 结论

该规则属于软件格式硬约束，不允许AI根据自然语言自行创造新的监控编码。
