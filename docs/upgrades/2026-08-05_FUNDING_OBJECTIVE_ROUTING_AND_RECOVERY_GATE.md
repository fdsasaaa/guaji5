# 2026-08-05 资金目标路由与回利闸门升级

## 根因

原系统已经能拒绝伪60档、短状态循环和缺少尾部边界的所谓耐久方案，但仍存在三个实用缺口：

1. 未正式区分耐久型和回利型；
2. 用户没有明确类型时，AI可能自行默认平倍或熟悉的倍率模板；
3. 回利型没有逐档机器复算，无法证明任意有效档首次命中后确实覆盖累计净亏损、当期成本和抽水并留下微利。

## 升级

- 新增正式协议 `12_方案资金目标分类与自适应路径协议.md`；
- 新增机器配置、Schema和证据模板；
- 新增确定性口述路由器；
- 新增耐久型与回利型语义校验器；
- 回利型逐档重算投注、返奖、返点、累计净亏损、命中净利和剩余本金；
- 未指定目标时强制进入 `AUTO_COMPARE`；
- 将资金目标证据纳入INTAKE、DIRECTOR、CONTRACT_FROZEN和VALIDATION；
- 将配置、单元测试、对抗测试和真实样例接入GitHub Actions。

## 已验证能力

- “生成耐久型方案”路由为 `DURABLE`；
- “生成回利型、中一期盈利”路由为 `RECOVERY_PROFIT`；
- “自主生成一套方案”路由为 `AUTO_COMPARE`；
- 同时出现两类目标时禁止擅自选择；
- 篡改任意档 `net_if_hit` 会失败；
- 奖金不足以完成回利会失败；
- 超过允许本金占用会失败；
- 耐久型未完成样本外验证却声称长期盈利会失败。

示例路径 `1,1,1,1,1,2,2,2,3,3,5,6,7` 在示例高奖经济模型中完成13档逐档复算；它只证明校验器能够根据玩法经济结构接受非固定模板，不代表真实彩种盈利结论。

## 边界

耐久型只说明资金暴露和尾部受控；回利型只在机器计算出的有效档位内成立。两者都不能替代真实数据、样本外验证、软件运行证据和平台限额核对。
