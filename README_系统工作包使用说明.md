# AI挂机方案生成系统工作包 V3.9.0

版本名称：智能功能调度与映射防呆版

## 最简单的使用方式

以后可以只把整个ZIP发送给AI，不附加任何文字。

AI收到后必须自动执行，不得先问“具体要做什么”：

```text
读取并校验工作包
→ 识别自主设计/用户指定/外部参考模式
→ 检索软件功能、189个角度、组合案例、负面模式和覆盖账本
→ 生成多个逻辑不同的候选族并执行硬门槛、评分和反方审查
→ 冻结不重复的新挂机方案套
→ 完成冻结、验证、随机基准和风险说明
→ 根据冻结方案逆向生成精简讲解PPT，旁白写入备注
→ 更新学习事件、索引、状态和总典
→ 分别返回新的方案套ZIP、PPTX和优化后的下一版工作包ZIP
```

## 默认三件套交付（分开发回）

1. 本次独立方案套/结果包ZIP；
2. 本次方案验证讲解PPTX（含逐页备注旁白）；
3. 更新后的系统工作包ZIP。

这三样默认**分别发送**，不再打包成一个总ZIP。

通常还会附带PPT逐页脚本Markdown和事实校验JSON。

## 没有新数据时怎样处理

- 有未处理的新数据：按完整闭环执行；
- 只有已使用历史数据：仍可生成新研究方案，但必须标记`REUSED_DATA`，不能冒充独立样本外；
- 没有可用开奖数据：生成E0/E1研究设计、PPT和更新工作包，不伪造回测；
- 没有合格候选：允许交付“本批没有合格方案”的复盘PPT。

## 用户也可以填写要求

可修改：

- `01_本次输入/用户本次要求.md`；
- `01_本次输入/本次参数与约束.json`；
- `01_本次输入/PPT样式与视频讲解偏好.md`。

用户明确要求优先于自动默认值，但不能覆盖防造假、防后验拟合和软件证据边界。

## 正式信息源

正式源是根目录00—11模块（含02A、05A）、十三个结构化索引/模板文件、`系统状态.json`和`当前任务.json`。
自动合并总典是便捷接管版，不能单独手工修改。

## 校验命令

```text
python 05_工具/build_total.py
python 05_工具/validate_governance.py
python 05_工具/validate_package.py
```

只有显示`VALIDATION_OK`，工作包才算完整。


## V3.6.2 交付实物完整性强制规则

每次完成任务时，`02_本次输出`不得只保存文件名、引用或SHA256。必须物理包含：

1. 本批独立挂机方案套ZIP；
2. 至少一个可直接导入软件的挂机方案TXT；
3. 本批方案讲解PPTX；
4. 三件套交付说明。

如果方案ZIP、挂机方案TXT或PPTX任意一项缺失，任务状态必须判定为`DELIVERY_INCOMPLETE`，不得宣称完整交付。


## V3.7.0 新规则

以后用户只上传工作包时，AI默认返回三份独立文件：

- 新方案套ZIP；
- 对应讲解PPTX；
- 更新后的新工作包ZIP。

工作包内部仍保留这些文件的副本，目的是便于归档和回滚，不代表用户必须下载一个总整合包。


## V3.7.2 PPT美工验收

PPT不得再只是纯文本页面。默认要求：统一主题、视觉层级、图表/流程/数字卡片、精简正文、备注旁白。若生成结果像普通文字稿，视为交付不合格。


## V3.7.2 PPT表达规则

PPT页面不得再出现类似 `B001`、`B002`、`REUSED_DATA`、`E4/E5` 这类内部编号或程序化字段。面向观众统一改成：方案1、方案2、第一个思路、第二条路径、复用同一批历史数据、已做历史验证、还缺少新增前向验证。


## V3.7.3 默认未加密规则

除非用户明确要求锁定，否则所有方案TXT的最后一行必须为：

```text
SchemeCreator=
```

校验器会同时检查工作包内TXT和独立方案ZIP内TXT，发现非空值即判定交付失败。


## V3.7.4 PPT实操教程风格

以后PPT不再默认做成完整研究报告。默认生成方式改为：

```text
提出一个真实问题
→ 用大白话讲规则
→ 用真实号码跑一遍
→ 只展示核心结果
→ 用一句话指出最大疑点
→ 给出固定前向观察计划
```

页面密度允许不均匀：核心技术页讲清楚，风险页和转场页可以非常简短。


## V3.8.0 静默方案总控

本版不再把“总导演”写成一个空泛角色，而是正式执行：

```text
识别任务模式
→ 定义真实验证问题
→ 检索功能/角度/案例/负面模式
→ 生成至少3个逻辑候选族
→ 硬门槛淘汰
→ 多维评分与反方审查
→ 冻结最终方案
→ 再生成PPT
```

内部保留候选数量、候选族、主要淘汰原因和未验证边界。默认对外不展示长篇内部推理，只给最终方案、简短理由和必要风险说明。

## 使用“仅作参考”外部方案

可以直接在聊天文字前写：

```text
仅作参考
（粘贴外部方案）
```

也可以填写：`01_本次输入/外部参考方案_仅作参考.md`。

系统不会照单全收，而会选择：

- 采纳并优化；
- 部分吸收并重构；
- 否定并给出替代方案。

## V3.8.1 直接执行确认豁免

以后只要用户发送工作包，或者发送“工作包 + 仅供参考方案/用户要求”，AI都直接完成创建、验证、PPT和工作包更新，不再等待二次确认。小缺口采用保守默认值并披露；只有文件损坏或完全无法读取时才报告阻断。

本版同时完成首个真实参考吸收运行测试：热5码六期方案已被采纳为验证对象，但随机和冷码对照显示其历史表现接近随机。


## V3.9.0 新规则

- 总导演必须做八层能力审议，不能只反复使用少数熟悉功能；
- 每批至少比较3种功能画像；
- 即使用户未提出倍投，也必须完成资金路径四路评审；
- 平倍仍是基准，但不再是未经比较的默认答案；
- 高级开某投某必须真正依赖触发号码，10行常量映射直接判失败；
- 固定五码应使用固定定位胆/定码轮换；模板缺失时阻断，不再滥用高级映射；
- 纯系统升级任务不强制制造无关方案和PPT。
